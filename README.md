# Ghostty setup for Codex CLI

Personal macOS terminal workspace: Ghostty + tmux + Broot + Starship, with
reproducible source patches and a local health check. No credentials or chat history.

## Что входит

| Компонент | Поведение |
|---|---|
| Ghostty | Catppuccin Mocha, непрозрачность 0.80, Shift+Enter, быстрый терминал ⌘⇧Space |
| tmux 3.8-balanced.4 | Плавный равномерный resize; Option+drag — обычное изменение двух соседей |
| Broot 1.61.0 | Свёрнутые папки с треугольниками, Git во вложенных репозиториях, `U` для untracked |
| Файловые действия | Cmd+клик — выбор нескольких файлов, Cmd+C — пути, Esc — сброс выбора |
| Finder / Quick Look | Cmd+V и drop в выбранную папку, Cmd+R — Finder, Space — просмотр |
| Исходники | Подсветка и перенос строк в отдельном Quick Look над терминалом |
| Codex 0.169.0 + патч | Клик по миниатюре или `[Image #N]` — крупный просмотр; Esc — назад |
| Статус tmux | Основные бинды, часы, время до сброса 5ч; клик по таймеру — точная дата |

Вставка PNG из буфера macOS использует исходные байты без повторного сжатия
полноразмерного скриншота (`codex-image-paste.patch`). Качество сохраняется;
изображения с EXIF-поворотом проходят обычную нормализацию.

Скрытие приложений по Dock/углу экрана обсуждалось, но **не реализовано**.

## Установка

Нужны macOS, Xcode Command Line Tools (`xcode-select --install`), Git и Homebrew.
Основной проверенный компьютер — Apple Silicon. Пути Homebrew определяются
автоматически; предусмотрен архив Codex для Intel, но весь Intel-сценарий здесь
пока не проверен. Это не установщик для Linux/Windows.

```sh
git clone https://github.com/Nickseen/ghostty-setup.git
cd ghostty-setup
zsh install.zsh --full --brew
```

Первая полная сборка скачивает зависимости и может занять десятки минут и много
места. Rust ставится в `.build`, глобальный toolchain не меняется. `--brew`
устанавливает зависимости из Brewfile; без него используются уже установленные.
Для предварительного списка назначений: `python3 setup.py install --full --dry-run`.

Установщик **заменяет перечисленные конфиги** Ghostty/tmux/Broot/Starship после
резервной копии. `.zshrc` дополняется идемпотентно. Существующий конфиг Codex,
авторизация, проекты, модели и MCP не копируются и не перезаписываются.
Все работающие задачи и серверы остаются запущенными.

После установки открой новую вкладку Ghostty и выполни:

```sh
tmux-balanced new -A -s myproject
```

Это отдельный сервер **balanced-v4**. Обычный launcher `tmux` вне tmux тоже выбирает
его; внутри существующей сессии сохраняет её сервер. Явные `-L`/`-S` сохраняются.
Обычный `tmux -V` проверяет клиентский бинарник,
а `tmux display-message -p '#{version}'` — сервер, который реально меняет панели.
Подключение новым клиентом к старому серверу не обновляет код сервера.
Существующие процессы между серверами автоматически не переносятся.

Проверить состояние:

```sh
ghostty-setup doctor
ghostty-setup repair
```

Если команда ещё не найдена: `python3 setup.py doctor`. Для применения темы
Ghostty — ⌘⇧,. Прозрачность fullscreen использует non-native fullscreen на
текущем рабочем столе: он не создаёт отдельный Space, нативные вкладки имеют
ограничения. Глобальная клавиша Ghostty и помощник Broot могут потребовать
разрешения macOS; установщик их самостоятельно не выдаёт.

## Обновления без исчезающих функций

Версии патчей закреплены в `versions.json`. Обновление официальных программ
Homebrew **не переключает** наши launchers на них. Проверенная приватная версия
остаётся выбранной, пока патч явно не перенесён и не проверен на новой.
Это сохраняет функции, но не означает автоматического получения новой версии
CLI или её исправлений. Общий сервер Codex может обновляться отдельно.

```sh
git pull --ff-only
zsh install.zsh --full
ghostty-setup repair
ghostty-setup doctor
```

Повторная установка использует имеющиеся локальные сборки. Для пересборки после
изменения патчей: `zsh install.zsh --full --rebuild` либо
`ghostty-setup build codex` (также `tmux`, `broot`) и полная установка.
Перенос на другую базовую версию — отдельное изменение `versions.json`, патчей,
сборочных скриптов и тестов, а не автоматическое применение старого diff.

Явный обход приватной сборки:

```sh
CODEX_OFFICIAL=1 codex
TMUX_OFFICIAL=1 tmux -L official new -s work
BROOT_OFFICIAL=1 broot .
```

### Если картинки не открываются

1. `ghostty-setup repair` восстанавливает `allow-passthrough all` на работающих
   default/старом balanced/текущем managed серверах. Это разрешает терминальную графику всем их панелям.
2. Выйди из затронутого Codex через `/quit` и открой ту же задачу через
   `codex resume ID`: поддержка графики определяется при запуске.
3. Нужен fullscreen-интерфейс **Codex**; он не равен fullscreen-окну Ghostty.
4. Для крупного просмотра нужен наш клиент. Уже работающий официальный процесс
   не получает патч от замены launcher; его надо переоткрыть.
5. Если исходный файл картинки из временной папки уже удалён macOS, повторное
   открытие не восстановит файл. Исторические вложения здесь не архивируются.
6. Если одновременно исчезли цвета и миниатюры, проверь `ghostty-setup doctor`:
   переменная `NO_COLOR` отключает в Codex также терминальную графику.
   `ghostty-setup repair --colors` убирает её из окружения серверов и сессий tmux.
   В уже открытой оболочке выполни `unset NO_COLOR`, затем снова открой Codex.
   Обычный `repair` сохраняет намеренно установленный `NO_COLOR`.

При создании пользовательского сервера из автоматизации, которая выставляет
`NO_COLOR=1` для своих логов, запускай `env -u NO_COLOR tmux-balanced …`:
tmux наследует окружение создавшего его процесса для новых панелей.

## Размеры панелей

`[40][30][50]` → увеличиваешь первую на 10 → `[50][25][45]`.
Если ту же левую границу двигать на 10 влево: `[30][35][55]` — обе остальные
панели растут поровну. Сначала кликни внутри нужной панели, затем тяни любую
её границу: именно выбранная панель меняется в обе стороны. Выбери третью и
передвинь её левую границу на 10 вправо: `[45][35][40]`. Линия больше не
переключает выбор на соседа. При уменьшении выбранной панели остальные
получают место, при увеличении — отдают.
Одинаковые абсолютные изменения сохраняют прежнюю разницу ширин доноров;
это **не** пропорциональное масштабирование всех ширин. Option+drag изменяет
только соседей. Две вертикально сложенные панели в другой колонке меняют
ширину вместе, сохраняя свои высоты. На пересечениях границ используется
стандартный resize. Подробности и ограничения: [TMUX_RESIZE.md](TMUX_RESIZE.md).

## Проверки и откат

```sh
python3 -m unittest -v test_setup test_broot_actions test_broot_file_import
python3 -m unittest -v test_tmux_balanced_native test_broot_folders test_broot_nested_git test_broot_scroll
python3 verify-broot-preview.py
```

Интеграционные проверки используют отдельные временные серверы и файлы.
Тесты CLI выполняются `build-codex-image-preview.zsh` при сборке. CI проверяет
перенос установки, сценарий обновления Homebrew и настоящие mouse events tmux.
Полная сборка Codex/Broot в CI не включена; их native-проверки запускались локально.

Копии конфигов сохраняются в `~/.config/ghostty-setup/backups/TIMESTAMP`.
Восстановление: `ghostty-setup restore ~/.config/ghostty-setup/backups/TIMESTAMP`.
Это восстанавливает конфиги и launchers, а не откатывает Homebrew, бинарники,
состояние окон или личную переписку. Частные бинарники остаются рядом с официальными.

Дополнительно: [Broot](BROOT_SHORTCUTS.md), [папки и Git](BROOT_FOLDERS.md),
[просмотр картинок Codex](CODEX_IMAGE_PREVIEW.md), [лицензии](THIRD_PARTY_NOTICES.md).
`legacy/` — старый эксперимент таймера внутри Codex; он не устанавливается.

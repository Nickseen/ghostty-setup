# Таймер в строке Codex

**Текущее решение: официальный Codex и таймер в tmux.** Собственная сборка не установлена и не подключена. Ниже сохранены сведения об экспериментальном патче.

Клик по синему таймеру в tmux переключает его на дату и время сброса пятичасового лимита: `29.10 => 05:35`. Повторный клик возвращает отсчёт. Дата отображается на том же месте и в том же стиле, используется местное время macOS. Остальные области строки tmux сохраняют свои действия.

Основа: официальный тег `openai/codex`, `rust-v0.165.0` (commit `360319d8dee62d87e2d59fc0c21805d79519cfed`).

Изменение добавляет `· ↻ 4ч 32м` к существующему полю `five-hour-limit`.
Время берётся из серверного `resets_at` активного аккаунта и сессии.
Строка обновляется при событиях интерфейса и каждые 30 секунд во время простоя.
Когда время истекло или сервер его не сообщил, таймер скрывается до получения новых данных.

Готовая сборка устанавливается отдельно:
`~/.local/opt/codex-reset/0.165.0/`.
Лаунчер `~/.local/bin/codex` запускает её, пока Homebrew использует версию 0.165.0.
После обновления Homebrew лаунчер запускает новую официальную версию; для возврата таймера патч нужно перенести на её исходники и пересобрать.

Официальный клиент остаётся доступен по `/opt/homebrew/bin/codex`.
Вход в аккаунт, история и настройки продолжают использовать обычный `~/.codex`.
Уже открытый Codex нужно закрыть через `/quit` и запустить снова, чтобы загрузить новый интерфейс.
Если текущий zsh запомнил старый путь команды, сначала выполнить `rehash`.

Файлы для повторения:

- `apply-codex-countdown.py` — точечные изменения исходников нужной версии;
- `codex-reset-native.rs` — расчёт отсчёта и проверки округления/истечения;
- `codex-reset-native-test.rs` — проверка поля через настоящий `ChatWidget`;
- `build-codex-countdown.zsh` — сборка и проверка изменённого поля;
- `install-codex-countdown.py` — установка отдельного пакета и лаунчера.

По итоговому выбору пользователя таймер оставлен в tmux рядом с часами.
